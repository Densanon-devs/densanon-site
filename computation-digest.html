Researchers attack AMD's Infinity Fabric to bypass hardware security protections with 'Fabricked'

Tom's Hardware
  • ETH Zurich disclosed 'Fabricked' — a software-only attack requiring no physical access that manipulates AMD Infinity Fabric routing during the EPYC boot sequence.
  • The attack breaks AMD SEV-SNP (Secure Encrypted Virtualization – Secure Nested Paging), allowing a malicious cloud hypervisor to silently read confidential guest VM memory.
  • Fabricked also enables forged attestation reports, destroying the trust guarantee cloud tenants use to verify VM integrity.
  • Impact is broadest in multi-tenant cloud environments where SEV-SNP is the primary hardware confidentiality boundary — a significant concern for confidential-compute workloads.

The Linux Kernel Working On A Rust-Based Untrusted Data API

Phoronix
  • A new Rust interface is being developed for the Linux kernel to handle user-space-supplied data with explicit untrust semantics, making it a compile-time error to pass untrusted bytes into routines expecting validated input.
  • This is a foundational safety primitive: drivers and subsystems written in Rust can annotate inputs as untrusted at the type level, preventing unsafe promotion bugs.
  • Extends Rust's kernel footprint beyond device drivers into OS-level memory-safety guarantees for kernel-user data boundaries.

Linux 7.2 Expected To Introduce "OPENAT2_REGULAR" To Avoid Tricking Secure Programs

Phoronix
  • A new OPENAT2_REGULAR flag for the openat2 syscall is queued for Linux 7.2, ensuring callers can require that only regular files — not symlinks, devices, or FIFOs — are opened.
  • Motivation: prevents TOCTOU and symlink-substitution attacks where a secure program opens what it expects to be a known regular file but gets redirected.
  • Security-sensitive applications (package managers, privilege-separated daemons, container runtimes) can harden file-open paths without custom validation logic.
