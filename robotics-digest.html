ROS2 Dev Container Feature + Workspace Update

ROS Discourse
  • Moves ROS2 dev environment setup from a monolithic pre-built Docker image to a modular VSCode Dev Container Feature, so developers can compose it into their own base images instead of inheriting a fixed one.
  • The companion VSCode ROS2 Workspace Template was updated to consume the new feature directly, cutting setup friction for new ROS2 projects and reducing duplicated Dockerfile maintenance.
  • Signals a broader shift in ROS tooling toward declarative, devcontainer.json-based environment configuration rather than hand-rolled Docker images per project.

Has a CPU shared-memory backend for rosidl::Buffer been explored?

ROS Discourse
  • Targets a concrete performance pain point: large variable-length payloads like images and point clouds currently incur serialization and copy overhead through rosidl::Buffer's existing backends.
  • Proposes a CPU shared-memory backend so same-host publishers and subscribers could exchange large messages without redundant copies, which matters for high-bandwidth sensor pipelines (e.g., LiDAR, camera streams).
  • The thread notes overlap with existing zero-copy mechanisms already in ROS2 (loaned messages, intra-process comms), pointing to a need for design coordination before implementation to avoid duplicating infrastructure.
