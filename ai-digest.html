AI Morning Digest

A quiet day with three tooling releases. Simon Willison shipped datasette-llm 0.1a11 with OpenAI-compatible endpoint support and revived datasette-vega after eight years, while Anthropic's sandbox-runtime v0.0.83 reworked how its Windows MXC backend gets its SDK.

Tools & Practical

datasette-llm 0.1a11

Simon Willison
  • datasette-llm is the intermediate plugin that lets other Datasette plugins share one LLM configuration; this release adds support for any OpenAI-compatible endpoint, wherever it is hosted.
  • That makes local servers such as LM Studio, Ollama and llama.cpp usable, configured via plugins.datasette-llm.default_model with model, model_name and api_base fields (for example http://localhost:1234/v1).
  • The post demonstrates Datasette Agent running on a local Qwen model, calling list_databases_and_tables and sql_query to answer a question about the Datasette content database.

datasette-vega 0.7

Simon Willison
  • datasette-vega, which renders Vega-Lite charts from a table or custom query, gets its first release since July 2018.
  • Version 0.7 updates it for compatibility with the latest Datasette alphas and adds cosmetic tweaks so it works better in Datasette Lite.
  • Datasette Lite has gained the ability to run JavaScript plugins like this one, and the README demo now links to a Datasette Lite session charting an airline-safety CSV.

anthropics/sandbox-runtime: v0.0.83

GitHub
  • @microsoft/mxc-sdk is now an optional peer dependency for the Windows MXC backend, so npm users of windows.backend: 'mxc' must install it themselves or pass windowsMxcSdk (#822).
  • initialize() now accepts windowsMxcSdk so an embedding program can supply its own MXC SDK, and the MxcSdk types are exported (#820).
  • spawnSandboxed() now accepts an env option for the child process (#822).
