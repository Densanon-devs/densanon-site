Give Your Coding Agents a Memory You Own

Hugging Face Blog
  • Funes is an open-source local-first memory layer for coding agents (Claude Code, Codex, and others) that persists session history across machines and agent switches, addressing the 'agents start from zero each session' problem.
  • Runs as a single binary with no ML runtime dependency: parses agent traces into a standardized turn-and-block format, chunks and embeds locally, and stores results in append-only local Lance datasets with combined vector/BM25 search plus cross-encoder reranking.
  • Exposes a `recall` tool the agent can call autonomously plus an `ask` command for direct user queries, with results linking back to raw source turns for verification, and supports sharing memories as private-by-default Hugging Face datasets with credential redaction before indexing.
  • Reported benchmarks: recall was 4-8x cheaper than manual handoffs on long sessions and outperformed built-in agent compaction — directly relevant to any local memory/context-continuity work on ultralight-coder or ulcagent.

Research & Papers

Speculative Macro Commit for Faster Tool-Using Agents

ArXiv cs.AI
  • Introduces Speculative Macro Commit (SMC): a two-tier setup where a large authoritative actor model produces the official trajectory while a faster speculative drafter model continuously predicts and executes future action chains, mined as recurring multi-action 'skeletons' from training traces.
  • When the actor's actual next action matches a drafted prediction, SMC commits the pre-executed steps/observations directly into the trajectory, cutting serial action-observation turn latency.
  • With Qwen models: 10.23% latency reduction over a Speculative Actions baseline (18.59% over sequential execution) on tau2-Bench Telecom, and 7.7%/44.9% wall-time reduction on AppWorld (with minor accuracy tradeoffs) — directly applicable to any of our tool-calling agent loops (ulcagent, densanon-core brain wire) looking to cut per-turn latency.
  • Code is publicly available per the authors, making this a testable technique rather than just a proposal.

Fresh Memory, Stale Plans: Dependency-Scoped Validation for Distributed LLM-Agent Memory

ArXiv cs.AI
  • Identifies a distributed multi-agent failure mode: agents can read the latest shared facts yet still execute a plan derived from a now-outdated requirement — state freshness doesn't imply plan validity.
  • Proposes PlanFence: plans explicitly cite the public records they depend on, and executors validate only the records relevant to pending actions, replanning or blocking on incomplete validation.
  • In controlled experiments across 30 live workflows, freshness-only systems executed obsolete plans in every task, while PlanFence completed all tasks with zero invalid actions; proactive sync wins at low churn, PlanFence scales better as churn/shared-data volume grows.
  • Relevant to any distributed/multi-agent memory design work (e.g. Story Director's FactLedger, multi-agent coder work) where stale plans built on since-superseded facts are a real risk.

Where Does Harness-Optimization Value Live? Localized Gains and the Budget-Splitting Trap in Self-Evolving LLM Agents

ArXiv cs.CL
  • HARNESSEVO decomposes an agent's harness into four separately evolvable slots (role/persona, task-strategy, tool/format-rules, reflection/control) and evolves each to find where optimization actually pays off.
  • Nearly all useful optimization value was localized in the reflection/control slot (leave-one-in gain of +0.119); the other three slots individually contributed close to nothing.
  • Uniform budget allocation across slots was actively counterproductive — spreading 64 rollouts across 4 slots (16 each) hurt performance versus concentrating budget on the high-value control slot, which reached a 0.761 success rate.
  • Task-dependent: on WebShop, no slot showed optimization potential at all, suggesting some tasks genuinely lack verbalizable control failures — a useful diagnostic before sinking effort into prompt/harness evolution on any of our agent harnesses.

Counterexamples as Feedback for Agent Self-Correction

ArXiv cs.CL
  • A-CEGIS is a framework testing whether agents can repair a wrong artifact after concrete feedback, arguing single-turn code-gen metrics understate this deployed-agent capability.
  • Tested on natural-language-to-regex synthesis: an agent proposes a pattern, an oracle validates it, and counterexamples drive iterative refinement.
  • Diagnostic counterexample feedback resolved 90% of tasks within four turns, vs. 17% for zero-shot generation, 27% for generic self-correction, and 23% for error-only feedback.
  • With hardening procedures, full evaluation reached complete task resolution at a mean of 2.7 turns and 77% robust success after targeted adversarial probing — a concrete pattern for self-correction loops in our own code-gen agents (ultralight-coder, multi-agent).

Probe Generalization as Subspace Selection for OOD Deception Detection

ArXiv cs.CL
  • Linear probes for detecting deceptive behavior in model activations often fail to transfer out-of-distribution; this paper finds that projecting activations onto a small subset of principal components from the training distribution restores most of that lost transfer performance.
  • Method uses an LLM judge to score principal components by whether their most/least-activated examples reflect transferable deception concepts, then probes only on the highest-scoring components.
  • Core insight: original probes over-weight source-specific surface features, while transferable directions encode deception concepts in more abstract, language-alignable terms — subspace selection, not just more data, drives OOD robustness.
  • Relevant to any of our AI-safety/grounding checks (is_grounded, ALM deception/anomaly work) that rely on activation probes or similar internal-state classifiers needing to generalize beyond their training domain.

R2Adapter: A Routing and Rewriting Adapter for Efficient Hybrid RAG

ArXiv cs.CL
  • Vanilla RAG handles simple queries efficiently but struggles with relational/multi-hop reasoning; graph-based RAG fixes that but at much higher inference cost — R2Adapter is a lightweight plug-in that dynamically routes each query to vanilla or graph-based RAG instead of using a fixed strategy or expensive LLM-based routing.
  • Uncertain graph-routed queries get rewritten to better expose their multi-hop structure, improving retrieval quality without extra supervision.
  • Across three multi-hop QA benchmarks, R2Adapter cut graph-based RAG usage by up to 59% while keeping answer accuracy comparable, and is model-agnostic/pluggable into existing vanilla or graph RAG pipelines.
  • Directly applicable to any RAG layer that currently pays graph-RAG cost on every query (ALM evidence retrieval, personal-memory-research substrate) — a cheap way to cut latency/cost without an accuracy hit.
