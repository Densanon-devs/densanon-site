Today's research skews heavily toward inference efficiency: papers attack sparse prefill attention, context-aware MoE routing, and Ising-inspired block pruning (with hard MMLU numbers behind it), alongside a hybrid causal/diffusion reasoning approach and a topology-based hallucination detector. Research & Papers

RBS-Attention: Radius-Bounded Sparse Prefill for Long-Context Large Language Models

ArXiv cs.AI
  • RBS-Attention targets the prefill bottleneck in long-context LLM inference, where dense self-attention over the full prompt dominates cost before generation even starts.
  • It addresses a specific failure mode in existing sparse block-selection methods: scoring blocks by their centroid can hide a highly relevant token buried inside an otherwise low-scoring block.
  • The radius-bounded approach is designed to keep those relevant tokens that centroid-based block selection would otherwise discard, cutting prefill cost without the accuracy loss of coarser sparsification.

Attention-Aware Routing: Coupling Routing and Attention in MoEs

ArXiv cs.AI
  • Standard Mixture-of-Experts routers select and weight experts per token using only that token's hidden state, which the authors say discards useful contextual signal.
  • Attention-Aware Routing (AAR) augments the router with additional temporal and spatial context, coupling the routing decision more directly to the attention mechanism instead of treating it as a separate lookup.
  • The goal is to let expert selection account for surrounding tokens and structure rather than routing each token in isolation.

CaLR: Causal Latent Revision for Robust Diffusion Reasoning

ArXiv cs.AI
  • CaLR targets a known tradeoff between the two dominant language model paradigms: autoregressive models reason step by step but get stuck in locally greedy choices, while diffusion language models refine the whole sequence in parallel but lack the strict causal structure reasoning chains need.
  • Causal Latent Revision brings causal structure into a diffusion model's latent refinement process rather than picking one paradigm over the other.
  • It fits the broader trend of hybrid AR/diffusion architectures that try to keep diffusion's parallel refinement while restoring AR-style causal reasoning.

Detecting Hallucination in LLMs: Tracing the Topological Signatures of Impaired Context Sharing

ArXiv cs.CL
  • The paper treats hallucination detection as a graph-topology problem, examining the shape of information flow through a model's attention graphs to separate hallucinated from non-hallucinated responses.
  • The core tool is Forman-Ricci curvature, a discrete geometry measure applied to the attention graph to identify structural patterns that indicate impaired context sharing between tokens.
  • The premise is that hallucinations leave a detectable topological signature in how information moves through attention, rather than only showing up in output-level inconsistency checks.

Memory That Looks Forward: A Zero-Inference Prospective Term for Personal Memory Retrieval

ArXiv cs.CL
  • Personal-memory retrieval is normally purely retrospective: it surfaces stored content resembling the current query but has no notion of what the user already committed to doing.
  • The paper adds a prospective term to the retrieval score that accounts for those commitments, designed to add zero inference cost at query time.
  • Commitments the user has already made get folded directly into the retrieval score, so pending intentions can surface alongside similarity matches instead of being invisible to a purely backward-looking retriever.

Transformers now runs llama.cpp quants

Hugging Face Blog
  • Hugging Face's Transformers library now loads GGUF quantized checkpoints directly through the standard from_pretrained() API instead of requiring llama.cpp itself.
  • On Apple Silicon, performance approaches llama.cpp, and models can be served through an OpenAI-compatible API via transformers serve, or fine-tuned directly from a GGUF checkpoint.
  • The initial release covers Qwen3.5 dense and MoE variants across quant levels from Q4_K_M (2.74 GB) up to BF16 (8.42 GB), using Unsloth's Qwen3.5-4B-GGUF as the reference model, and requires PyTorch 2.12.1+ with the Transformers main branch.

Pruning LLMs Like a Physicist: Block Removal as an Ising Optimization Problem

Hugging Face Blog
  • The post reframes transformer block pruning as a constrained binary optimization problem mapped onto an Ising model: each block is a binary keep/remove variable, and a Hessian computed once from calibration data captures both individual block importance and pairwise interactions between blocks.
  • That interaction term is the key departure from existing mean-field pruning methods, which score blocks independently and ignore that removing one block changes how much another block matters.
  • On Llama-3.3-70B-Instruct at 50% depth removal, their method scores 76.9 MMLU versus 54.0 for a competing block-influence baseline; tabu search and quantum-inspired solvers reach the same optimal configurations in seconds that brute-force GPU search took about 2 days to verify on smaller problems (roughly 29 billion configurations).
  • Tests also covered Qwen3-14B and NVIDIA-Nemotron-3-Nano-30B, a hybrid Mamba2/attention/MoE architecture.

tokenizers v1: encode, decode and scaling, measured

Hugging Face Blog
  • Tokenizers v1 keeps the same output and API as v0.23 (same call, same ids) while rewriting the internals: the workspace is split into modular crates, regex-based splitting is replaced with SIMD bitstream operations, and the merge loop uses intrusive linked lists in preallocated buffers instead of repeated allocations.
  • It adds thread-local word caching to avoid reprocessing repeated pre-tokens, plus native parallelism with per-thread scratch buffers.
  • Measured on an Apple M4 Max, the release candidate encodes 3 to 30 times faster than v0.23 on a single thread, and scales to 76% of linear speedup across eight worker threads.

Jev introduces a new shape of LLM - System One, aka Decision Models

Simon Willison
  • TypeSafe AI's Jev is the first example of what it calls 'System One models' (Simon Willison prefers 'decision models'): instead of generating text, it takes unstructured input and returns typed, probabilistic decisions with confidence scores.
  • It handles three question types: yes/no (0-1 confidence), multiple choice (a probability distribution over options), and scored ratings across a numeric range; TypeSafe summarizes it as 'unstructured state in, typed probabilistic decisions out.'
  • Pricing charges only for input tokens at $0.042 per million, undercutting GPT-5 Nano, with output free; questions process in parallel so many queries take about as long as one.
  • Early community use cited includes spam detection, label suggestion, prioritization, search reranking, and even game-playing and utility functions.

Cloudflare Python Workers are now generally available

Simon Willison
  • After a two-year preview, Cloudflare has made Python a fully supported, stable language on its Workers platform, crediting developers Gyeongjae Choi, Dominik Picheta, and Hood Chatham, the latter two being Pyodide core maintainers.
  • Python code compiles to WebAssembly via Pyodide and runs inside Cloudflare's V8-based workerd runtime; both the multiprocessing and threading modules are non-functional in that WASM environment.
  • The local dev tool pywrangler, published on PyPI as workers-py, simulates the full production stack locally, including running Pyodide-in-WASM inside V8; the workerd binary itself is about 123MB.
