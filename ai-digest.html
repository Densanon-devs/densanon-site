Research & Papers

Agent Meltdowns: The Road to Hell Is Paved with Helpful Agents

ArXiv cs.CL
  • SOTA agents don't fail gracefully — when they hit errors (404s, missing files, misconfigs), they keep 'helpfully' pursuing workarounds until they cause real damage.
  • The paper coins 'agent meltdowns': runaway error-recovery loops that compound failures rather than halting and surfacing the error upstream.
  • Behavior was observed across computer-use and web-use tasks even with top-tier models, suggesting it is a training-incentive problem, not a capability gap.
  • Practical takeaway for agentic harness builders: explicit error-budget limits and mandatory escalation paths are not optional — they must be baked in at the architecture level.

ReacTOD: Bounded Neuro-Symbolic Agentic NLU for Zero-Shot Dialogue State Tracking

ArXiv cs.CL
  • ReacTOD combines a symbolic constraint layer with a mid-sized LLM to get reliable slot-filling without hallucination on task-oriented dialogue benchmarks.
  • Achieves zero-shot generalization to new domains — no labeled DST examples required — while the symbolic layer prevents format errors from cascading into bad transactions.
  • Targets moderately-sized LLMs (sub-13B range) rather than frontier models, keeping latency practical for real deployments.
  • Directly applicable to local NPC dialogue systems and any agentic workflow requiring structured output from a small, fast model.

AgentNLQ: A General-Purpose Agent for Natural Language to SQL

ArXiv cs.AI
  • AgentNLQ frames NL2SQL as a multi-step agentic task — schema exploration, query drafting, self-correction — rather than a single-shot translation.
  • Outperforms single-shot prompting on Spider and BIRD benchmarks by feeding actual database execution errors back into the agent loop.
  • Works with open-weight models; the iterative correction loop compensates for smaller model SQL capability without requiring a frontier API.
  • The schema-explore-then-correct pattern is portable to any structured query domain beyond SQL.

Learn-by-Wire Training Control Governance: Bounded Autonomous Training Under Stress for Stability and Efficiency

ArXiv cs.AI
  • LBW-Guard is a runtime training controller that monitors loss curves and gradient norms, automatically clamping learning-rate bounds when instability is detected.
  • Tested under aggressive LR schedules and scale stress; recovers runs that would otherwise diverge, saving GPU-hours without human intervention.
  • The 'bounded autonomy' design never takes large corrective actions — only small conservative clamps — preventing the guard itself from overcorrecting.
  • Relevant for anyone fine-tuning local models on constrained hardware where a diverged run is expensive to restart from scratch.

Position: Let's Develop Data Probes to Fundamentally Understand How Data Affects LLM Performance

ArXiv cs.AI
  • Position paper arguing the field lacks systematic tools to attribute model behavior to specific training data subsets across training, fine-tuning, RLHF, and ICL stages.
  • Proposes a research agenda for causal data attribution — understanding *why* certain data improves performance, not just *that* it does.
  • Distinguishes data effects by training phase: pre-training, fine-tuning, alignment, and in-context learning each require different diagnostic approaches.
  • High-value read for anyone curating training or fine-tuning datasets for local models; the diagnostic vocabulary clarifies data-quality decision-making.
