Runtime Governance for Agentic AI: Action-Boundary Control with Trusted Provenance and Fail-Closed Execution

ArXiv cs.AI
  • Proposes 'Aegis,' a runtime governance layer where the model only proposes actions and a separate trusted runtime decides whether to execute them - moving safety enforcement out of the prompt and into server-side policy evaluation with cryptographic provenance tracking, defaulting to rejection under uncertainty.
  • High-stakes actions route through a quorum-based 'senate-style' authorization requiring multiple independent approvals rather than one model call being able to unilaterally act.
  • In sandbox tests across 6,300 rows, prompt-conditioning alone produced 79 risky outcomes while Aegis governance produced zero risky completions across 2,100 governed rows - though the authors caution this supports narrow sandbox-system claims, not general autonomous-agent safety.

GxP-Agent: Process-DAG Topology for Reliable Clinical Trial Programming with LLM Agents

ArXiv cs.AI
  • Across 11 single-shot attempts with five frontier models, none produced a valid subject-level clinical trial analysis dataset - plain LLM code generation fails catastrophically on this regulated task.
  • GxP-Agent instead encodes regulatory process knowledge as a directed acyclic graph, splitting dataset generation into 15 specialized nodes with validation gates and conditional retries; with Claude Sonnet 4.6 it hit 100% structural accuracy (49/49 variables) across three independent runs, versus 59.2% for a RAG baseline.
  • The DAG structure also lifted a weaker model (GPT-4.1) from 0% to 59.2% accuracy, and generalized to adverse-events data at 100% on the first attempt - evidence that encoding domain process as graph topology, not more LLM reasoning, is what fixes reliability.

The Price of Thinking: Reasoning Effort as a Model-Specific API Contract

ArXiv cs.AI
  • In a preregistered test of 30 AIME 2026 problems (5 replications each) on Claude Sonnet 5, explicitly requesting high reasoning effort cost about $0.01 more per call than omitting the parameter, with no statistically significant accuracy gain.
  • Cost per correct answer was $0.08665 for explicit high-effort versus $0.07662 with the parameter omitted - the 'thinking harder' setting bought no measurable benefit here, just a premium.
  • The authors note reasoning-effort semantics are documented inconsistently across providers (and even within a single provider), making it hard for API consumers to reason about what they're actually paying for.

Institution-Specific LLM Prompting Recovers PHI That De-identification Systems and Their Gold Standards Both Miss

ArXiv cs.CL
  • On 100 pediatric oncology notes with 5,322 labeled PHI spans, in-context-prompted LLMs beat a purpose-built de-identification system (Stanford TiDE): F1 0.918 vs 0.779.
  • Feeding the LLM institution-specific 'missed category' examples (hospital abbreviations, building names, internal codes) recovered 79% of PHI that the original gold-standard annotations and standard systems had missed entirely.
  • The final calibrated prompt hit recall 0.981 (F1 0.907) and surfaced 414 candidate annotation gaps, 227 of which were confirmed as real previously-missed PHI - a reminder that de-identification benchmarks can undercount the problem they're meant to measure.

The Problem Is the Problem: Towards Scalable Mathematical Discovery

ArXiv cs.AI
  • Argues the real bottleneck in AI-assisted math research isn't model reasoning capability but the human effort spent selecting good problems upfront and reviewing AI-generated results afterward.
  • Proposes FAR (Find, Attempt, Recommend): instead of a human picking one problem, the human specifies a research direction and the system searches a literature corpus for candidate problems, cascading them through filters toward human review.
  • In testing, FAR searched 5,245 combinatorics papers, surfaced 6,453 candidate problems, and filtered down to just 77 for human attention - automating the triage stage that currently consumes scarce expert time.

Qwen 3.8 27B scores 52 on the Artificial Analysis Intelligence Index

Simon Willison
  • Qwen 3.8 27B scored 52 on the Artificial Analysis Intelligence Index - identical to GPT-5.6 Luna (max) and just one point behind GLM-5.2 and DeepSeek V4 Pro (both max variants).

How Much Memory Does Your Agent Actually Need?

Hugging Face Blog
  • IBM Research's ALTK-Evolve self-distills behavioral guidelines from an agent's own past trajectories and injects them at inference time with no weight updates - the method transferred across eight different models without human annotation.
  • How much memory helps depends on model strength: a 117B MoE model gained +16.1pp task completion from selective retrieval of high-confidence, task-specific guidelines, while a 671B MoE model gained +9.5pp from full guideline sets - bigger context isn't always better.
  • Selective retrieval added only +5% token overhead versus +51-78% for dumping in comprehensive guideline sets, and gains were larger on stricter 'all task variants must succeed' metrics - suggesting memory mainly prevents edge-case failures, not just raises average completion.

Multi-Vector (Late Interaction) Embedding Models with Sentence Transformers

Hugging Face Blog
  • Late-interaction models keep one vector per token instead of compressing a document into a single vector, then score with MaxSim: for each query token, take its highest similarity against any document token and sum those maxima - preserving detail single-vector embeddings average away.
  • The quality gain has a real storage cost: encoding 4,874 passages produced 608,414 token vectors needing 311.5 MB, versus 7.5 MB for a dense single-vector model on the same data (~40x more storage); token pooling can cut that roughly in half with minimal quality loss.
  • Sentence Transformers v6.0 ships a unified MultiVectorEncoder API that loads PyLate/ColBERT/ColPali checkpoints interchangeably for text, image, audio, and video retrieval via the same encode_query()/encode_document()/similarity() calls, and integrates with Qdrant/Weaviate.
