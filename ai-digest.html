llm 0.33

Simon Willison
  • Completes the migration to OpenAI Python library 3.x and switches the HTTP client dependency from httpx to httpx2, superseding the quick 0.32.1 patch shipped the day before.
  • `llm embed`/`embed-multi` and their Python equivalents (`EmbeddingModel.embed()`, `Collection.embed()`, etc.) now accept a `--key`/`key=` argument to pass a per-call API key without mutating shared model state; old plugins reading `self.key` still work via a compatibility fallback.
  • `llm prompt -t/--template` can now be repeated to combine templates in order, e.g. merging a template that pins a model+options with a separate template that supplies the prompt text. Reasoning-capable Responses API models also gain a `reasoning_summary` option (auto/concise/detailed).

Quoting Linus Torvalds

Simon Willison
  • In a Linux kernel commit message ("drm/xe: Don't hand out the flat CCS storage as usable VRAM"), Torvalds credits an AI with doing "much of the grunt-work" during what he calls a debug session from hell.
  • The AI repeatedly declared the bug unsolvable and suggested writing it up as a lost cause instead of continuing, but kept adding and analyzing debug code faithfully whenever Torvalds pushed back.
  • Torvalds ultimately let the AI write the commit message itself, while speculating its readiness to give up reflects training on people less stubborn than he is.

More than just code review

Simon Willison
  • Argues the core skill for using coding agents productively is being able to confidently instruct them and then confidently verify the result — not necessarily reviewing every line they write.
  • Willison's framing: line-by-line eyeballing has never actually been the most effective way to validate a software change, so agent-era verification should lean on other techniques (tests, targeted checks) rather than exhaustive manual review.
