Auto mode is now the default in Claude Code for Pro, Max, and Team plans

Simon Willison
  • Anthropic is flipping Claude Code's 'auto mode' to the default for new sessions on Pro, Max, and Team plans starting August 14, 2026 -- a strong signal they now consider automated model/tool routing production-ready rather than experimental.
  • The change applies to new sessions specifically, so existing pinned-mode sessions won't switch automatically -- the rollout is gradual rather than a hard cutover.
  • Relevant to any project doing its own model/tool routing (PIE's router+experts, ultralight-coder's model selection) as a real-world data point on how a major vendor is tuning auto-routing confidence.

anthropics/anthropic-sdk-ruby: v1.61.0

Anthropic GitHub
  • Session budgets land in the official Ruby SDK -- a built-in cost/token cap per session, useful for long-lived agent sessions that need a hard stop instead of manual token tracking.
  • 'Pinned inference location' is a new API-level primitive giving explicit control over which region/cluster serves a request -- relevant for latency-sensitive or data-residency-constrained deployments.
  • Skills auto-loading from GitHub lets SDK clients pull skill definitions directly from a repo at runtime instead of bundling them locally -- the same feature shipped same-day in the CLI (v1.22.0), confirming a coordinated platform-wide rollout.

anthropics/anthropic-sdk-ruby: v1.60.0

Anthropic GitHub
  • New beta flag `mid-conversation-tool-changes-2026-07-01` allows changing the available tool set mid-conversation rather than only at session start -- useful for agent architectures that swap tool access by task phase (e.g. planning vs execution).

  • The same beta landed same-day in the Java SDK (v2.53.0) and C# SDK (v12.40.0), confirming this is a core API capability being rolled out across all official SDKs simultaneously, not a language-specific experiment.

anthropics/anthropic-sdk-csharp: Bedrock: v0.11.1

Anthropic GitHub
  • Bug fix addresses a URL-port-dropping bug when the C# SDK adapts requests for AWS Bedrock or Google Vertex hosting -- anyone self-hosting Claude behind a non-default port (a local proxy or gateway) would have hit silently-broken requests before this fix.
  • The identical fix (PR #137) was also released as the Vertex-adapter package (v0.5.2) -- upgrading either package resolves the issue for both cloud backends since it's the same underlying commit.
  • Low-priority patch unless actively running Bedrock/Vertex-hosted Claude through a non-standard port; otherwise safe to defer.

Anthropic GitHub
