A Virtual Member of a Community of Practice for the Society of Petroleum Engineers: From Prototype to Deployment

ArXiv cs.CL
  • ATHENA, a RAG-based virtual assistant for petroleum engineers, was upgraded with multi-document retrieval, answer-validation checks, and targeted proactive knowledge dissemination.
  • In a study with 75 SPE members on well-planning tasks, the upgraded version markedly improved both productivity and performance equality versus prior state-of-the-art RAG baselines.
  • The system has moved past prototype status and is now live in the SPE Research Portal for the society's membership, a rare documented prototype-to-production RAG deployment.

Automatic bioinformatic software named entity recognition from literature

ArXiv cs.CL
  • SNAIL is a hybrid NER system pairing lexical pattern-matching with a SciBERT-based semantic model that uses token-masking to sharpen entity-focused representations.
  • Its training corpus was built via citation-hinted extraction with LLM-assisted distillation rather than pure manual annotation.
  • On two benchmarks and real-world articles, SNAIL beat both the domain-specific bioNerDS2 baseline and general LLMs (ChatGPT, Gemini, Grok, Claude), then was used at scale to surface journal-level differences in bioinformatics tool usage.

Asymmetric Attention Heads: Structured Head-Wise Context Allocation for Transformer Attention

ArXiv cs.CL
  • Proposes Asymmetric Attention Heads (AAH), which treats each attention head's causal context window as an explicit, individually assignable parameter instead of giving every head the same full context span.
  • Heads are grouped by feature statistics into a hierarchy, each getting its own local window size, while staying drop-in compatible with standard multi-head attention interfaces.
  • On 4096-token sequences, several AAH variants beat full-attention baselines on validation loss; the authors also introduce an Attention Coverage Ratio (ACR) metric to diagnose how context windows get routed.

Hallucination as a Feature, not a Defect: Evaluating a multi-agent architecture to transform speculative language-model outputs into testable scientific hypotheses

ArXiv cs.CL
  • Instead of suppressing hallucination, the system routes it through three agents: a high-entropy generator producing speculative ideas, a low-entropy semantic bottleneck that cuts noise/repetition, and a web-grounded evaluator that checks feasibility - an "Epistemological Friction loop."
  • Results were mixed: plain direct prompting was weak, but the full multi-agent architecture showed no consistent edge over simpler self-reflection baselines across originality, feasibility, diversity, and grounding metrics.
  • The architecture's value shows up mainly when hypotheses must satisfy hard physical, empirical, or institutional constraints, suggesting structured constraints (not raw hallucination) are what make speculation useful.

Up to 3.2x Faster Inference with LFM2.5-DSpark

Hugging Face Blog
  • Liquid AI released DSpark draft-model checkpoints for three LFM2.5 models (1.2B, 2.6B, 8B-A1B) that add a speculative decoding path without changing output quality.
  • The ~300M-parameter draft models combine a parallel backbone for multi-token candidates, a sequential head for token dependencies, and a confidence-scheduled verifier that prunes low-confidence guesses.
  • Measured speedups: up to 3.18x on H100 GPU and 2.87x on-device (M4 Max), with a 57% latency reduction for function-calling on the 2.6B model; the 8B MoE model only hit 1.21x on-device due to MoE constraints.

ChatGPT search now uses the site:operator at scale

Simon Willison
  • Data from Promptwatch shows ChatGPT Search's use of the site: operator jumped from 0.3-0.5% of queries to 16-17% on August 8, right after a GPT-5.6 update billed as making answers "more reliable with facts."
  • The shift signals OpenAI is leaning harder on domain-scoped retrieval rather than open web search, feeding the emerging GEO (Generative Engine Optimization) industry - SEO for chatbot answers.
  • A follow-up report found ChatGPT also appears to have reduced how often it cites Reddit as a source, a reminder that source-selection behavior can shift silently with model updates.

A shot-scraper-style JSON API on Bun 1.4's new Bun.WebView

Simon Willison
  • Bun 1.4 ships Bun.WebView, native browser automation (macOS WebKit or CDP-controlled Chromium) built into the Bun runtime itself, no Puppeteer/Playwright dependency required.
  • Simon Willison built a roughly 150-line, zero-dependency TypeScript service exposing /javascript, /screenshot, and /healthz endpoints, spinning up one browser tab per request for concurrency.
  • The prototype ran in a 192-256MB container against complex pages, suggesting Bun.WebView is a lightweight alternative for scraping/screenshot microservices.
